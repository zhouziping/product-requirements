# 需求文档仓库

用于整理、澄清和维护产品需求。当前仅建立文档结构，尚未录入具体产品的业务需求；本仓库内容不代表功能已经实现或上线。

## 文档导航

- [维护约定](AGENTS.md)：人员与自动化助手共同遵循的编辑、事实核实和交付规则。
- [需求概述](docs/requirements-overview.md)：需求索引、已确认信息和待确认事项。
- [需求模板](templates/requirement.md)：新增需求的起点。

## 新增或更新需求

1. 阅读维护约定，确认本次请求的目标、可公开引用的依据和范围。
2. 从最新 `main` 创建工作分支。新增需求时，复制模板至 `docs/requirements/<需求编号或简短名称>.md`；该目录按需创建。
3. 记录已确认事实、建议方案和待确认问题，不将缺失信息补写成事实。
4. 更新需求概述中的索引，保证标题、状态和链接与需求正文一致。
5. 自查后提交 PR，说明变更、依据、检查结果以及仍待确认的事项。
6. 由人工审阅并手动合并。PR 提交、审阅通过或文档合并均不表示需求已获业务批准或已实现。

首次使用时，可先补充产品背景、目标用户、需求负责人及可公开的需求依据。尚无信息的字段保留为“待确认”，不要填入虚构业务或示例指标。

## 维护边界

以需求文档维护为主，不默认开展产品实现、部署或基础设施变更。不在仓库中放入凭据、个人信息、未获授权公开的聊天内容或内部文档。插件运行提示词与实际接单策略由部署侧单独维护，修改仓库文档不会自动改变运行配置。
