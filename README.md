# 需求文档仓库

用于整理、澄清和维护产品需求，按**功能规格、增量 Story、验收场景、验证记录**四类文档组织。已收录待业务确认的增量需求和验收场景，详见[需求概述与索引](docs/requirements-overview.md)；尚无产品验证执行记录，不代表功能已实现或上线。

## 文档导航

- [维护约定](AGENTS.md)：事实核实、编辑边界与人工合并规则。
- [需求概述与索引](docs/requirements-overview.md)：产品背景待确认项及四类文档索引。

| 文档类型 | 目录与填写说明 | 模板 | 用途 |
| --- | --- | --- | --- |
| 功能规格 | [功能规格目录](docs/features/README.md) | [功能规格模板](templates/feature-spec.md) | 描述功能整体规则、范围与边界，区分已确认内容和建议 |
| 增量 Story | [增量 Story 目录](docs/stories/README.md) | [增量 Story 模板](templates/story.md) | 记录相对某一规格版本的新增、修改或移除及其依据 |
| 验收场景 | [验收场景目录](docs/acceptance/README.md) | [验收场景模板](templates/acceptance-scenario.md) | 记录可观察的前置条件、操作和预期结果，不记录执行通过结论 |
| 验证记录 | [验证记录目录](docs/verification/README.md) | [验证记录模板](templates/verification-record.md) | 记录实际执行对象、环境、结果与证据，不代替业务确认 |

原[需求模板入口](templates/requirement.md)保留为四类模板的导航，不再创建单一大文档。

## 新增或更新文档

1. 阅读维护约定，确认请求目标、范围及可公开的依据；从最新 `main` 创建工作分支。
2. 按用途复制相应模板到对应目录，使用稳定、易辨识的文件名和编号。模板提示不是业务要求，缺失信息保留“待确认”。
3. 功能规格维护整体规则；增量 Story 记录变更前基线、变更内容与关联规格。明确区分已确认规则与未确认变更，不把 Story 提议直接当成现行规则。
4. 验收场景引用对应规格条目和 Story（如有）；实际验证后单独新增验证记录，引用场景及被验证的具体版本。没有执行时不得填写通过。
5. 更新需求概述索引和引用链接。复制模板后调整相对链接，并将待确认的关联替换为真实文档链接，不创建虚构条目。
6. 完成差异和文档检查后提交 PR，由人工审阅并手动合并。PR 获批或文档合并不等于业务批准、验证通过、实现完成或上线。

首次使用时，可先补充产品背景、目标用户、需求负责人及可公开依据。无依据的信息保持待确认，不填写虚构业务或示例指标。

## 维护边界

以需求文档维护为主，不默认开展产品实现、部署或基础设施变更。不在公开仓库中放入凭据、个人信息、未获授权公开的聊天内容或内部文档。插件运行提示词与接单策略由部署侧单独维护，修改仓库文档不会改变运行配置。
